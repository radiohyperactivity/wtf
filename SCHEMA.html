WtF Schema

Entity-relationship diagram in crow's foot notation. Source: SCHEMA.md.

  • class_attribute (attribute, option_default) and value (attribute, option_value) are composite foreign keys to attribute_option (attribute, id), so an option always belongs to the same attribute.
  • class.parent and location.parent form trees; triggers prevent cycles.
  • The datatype of a value or default is checked against attribute.datatype by triggers; url is stored in the text column.
  • Each unit belongs to one unit_family of a quantity, and converts to the quantity's base unit as value × base_factor + base_offset. Quantities, families and units have integer ids.
  • item.code, location.code and stock.code are label codes from one shared sequence (code_sequence), so they are unique across all three tables; the API shows them in Crockford Base32.
  • class_attribute.per_unit puts an attribute's values on stock rows (stock_value) instead of on the item (value); required makes new items or stock rows need a value unless there is a default.
  • An attachment is a file: the SHA-256 hash of its content (the bytes live in wtfd's files directory, named by it), its MIME type and a title. The mapping tables link it to items, stock rows, locations and classes; one that nothing links to any more is deleted.
  • photo on item, stock, location and class refers to attachment (not drawn): one of the object's own attachments, and an image.
  • history is written by a trigger on every data table and on account; accounts are never deleted, only marked deleted, so history can always refer to them.
  • data_version holds a change counter for the class and location tables (one row each), maintained by statement-level triggers. It has no foreign keys.
  • attribute.unit and item.unit are the unit numbers are entered in; on output they are scaled within its family, or shown in the unit itself with unit_lock. The numbers themselves (values, defaults, stock quantities) are stored in the base unit. An item without a unit counts pieces.
