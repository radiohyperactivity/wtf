WtF Schema

Entity-relationship diagram in crow's foot notation. Source: SCHEMA.md.

  • class_attribute (attribute, option_default) and value (attribute, option_value) are composite foreign keys to attribute_option (attribute, id), so an option always belongs to the same attribute.
  • class.parent and location.parent form trees; triggers prevent cycles.
  • The datatype of a value or default is checked against attribute.datatype by triggers; url is stored in the text column.
  • Each unit converts to its quantity's SI base unit as value × base_factor + base_offset; the base unit is the one with factor 1 and offset 0.
  • item.code, location.code and stock.code are label codes from one shared sequence (code_sequence), so they are unique across all three tables; the API shows them in Crockford Base32.
  • class_attribute.per_unit puts an attribute's values on stock rows (stock_value) instead of on the item (value); required makes new items or stock rows need a value unless there is a default.
  • An attachment belongs to exactly one item, stock row, location or class (exactly one of the four foreign keys is set). file is the stored content, by SHA-256; the bytes live in wtfd's files directory.
  • tenant: every tenant-scoped table (class, attribute, attribute_option, class_attribute, item, value, location, stock, stock_value, attachment, session) also has a tenant column referencing it, and all references between those tables are composite foreign keys (tenant, x) → (tenant, id). These tenant columns are not drawn, to keep the diagram readable.
  • history is written by a trigger on every tenant data table and on account; accounts are never deleted, only marked deleted, so history can always refer to them.
  • data_version holds a change counter for the class and location tables (one row each), maintained by statement-level triggers. It has no foreign keys.
  • attribute.unit_group and item.unit_group name the group a number is scaled between on output. The numbers themselves (values, defaults, stock quantities) are stored in the base unit. An item without a unit group counts pieces.
